# Plan 2: Auth (better-auth email OTP + Drizzle/D1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Email-OTP sign-in end to end: Drizzle over D1, better-auth mounted in the Hono worker, session middleware, `/api/me`, and a minimal (undesigned) login flow in the SPA.

**Architecture:** better-auth is instantiated PER REQUEST via a `createAuth(env)` factory (D1 bindings don't exist at module scope on Workers) with the Drizzle adapter over `drizzle-orm/d1`. Schema flows better-auth CLI → Drizzle TS → drizzle-kit SQL → wrangler d1 migrations; the same SQL files feed tests via `readD1Migrations`. OTP email goes out through Resend raw fetch; without `RESEND_API_KEY` (dev/test) the OTP is captured in a module-scope variable instead.

**Tech Stack:** better-auth ^1.6, drizzle-orm + drizzle-kit, @better-auth/cli, Resend REST API, existing Hono/vitest-pool-workers/Vite stack.

**Spec:** `docs/superpowers/specs/2026-08-05-pwa-rework-design.md` §3 (auth), §2 (data model)
**Research (read before implementing):** `.superpowers/research/better-auth-workers-2026-08.md` — exact code patterns + gotchas; briefs below reference its sections.

## Global Constraints

- Branch: all work on `feat/plan2-auth`. Never commit to `main`.
- Per-request `createAuth(c.env)` factory — NEVER `betterAuth()` at module scope (research §1).
- Drizzle adapter path (research §1b) — NOT the native D1 binding path, NOT hand-rolled Kysely D1Dialect.
- Session cookies: defaults (same-origin SPA) — no `defaultCookieAttributes` override (research §4).
- emailOTP: defaults otpLength 6, expiresIn 300, allowedAttempts 3, rateLimit `{window:60,max:3}` — set explicitly for visibility (research §2).
- Resend via raw fetch, secret `RESEND_API_KEY` via `wrangler secret put` — never in wrangler.jsonc or committed files (research §7). Dev/test fallback: no key → capture OTP in module variable + console.log.
- Migrations dir: `drizzle/` at repo root; `wrangler.jsonc` gets `"migrations_dir": "drizzle"`; drizzle.config.ts `out: "./drizzle"`. Local-file generation only — no `d1-http` credentials in config (research §6 note).
- `pnpm typecheck && pnpm test` green at every task's end; every commit carries the standard trailers used on this branch.

- [ ] **Step 1: `worker/src/email.ts`**

```typescript
type EmailEnv = { RESEND_API_KEY?: string };

let lastDevOtp: string | null = null;
export const getLastDevOtp = () => lastDevOtp;

export async function sendOtpEmail(env: EmailEnv, to: string, otp: string) {
  if (!env.RESEND_API_KEY) {
    lastDevOtp = otp;
    console.log(`[dev] OTP for ${to}: ${otp}`);
    return;
  }
  const res = await fetch("https://api.resend.com/emails", {
    method: "POST",
    headers: {
      Authorization: `Bearer ${env.RESEND_API_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      from: "Roaster Me <auth@roaster-me.dev>",
      to: [to],
      subject: "Your sign-in code",
      html: `<p>Your code is <strong>${otp}</strong>. It expires in 5 minutes.</p>`,
    }),
  });
  if (!res.ok) throw new Error(`Resend send failed: ${res.status} ${await res.text()}`);
}
```
