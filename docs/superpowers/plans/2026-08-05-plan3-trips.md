# Plan 3: Trips CRUD + Crew Home (tokens applied) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crew can enter multi-leg trips (with report time), see them on a crew home screen matching the approved hybrid-v2 design (dark instrument tokens, report-time-first hierarchy), all times timezone-correct.

**Architecture:** New D1 tables `trips`/`flights` (Drizzle, same migration pipeline as auth) + minimal `airports` reference (IATA → IANA tz, seeded from committed JSON). Hono CRUD under `/api/trips` behind the existing session middleware with a single ownership-check helper. Web: design tokens as Tailwind v4 `@theme` variables from the approved mockup, pure timezone/countdown utils (heavily unit-tested), entry form (leg editor with report-time auto-fill = departure − 90 min, editable), crew home per research hierarchy.

**Tech Stack:** existing stack + `@date-fns/tz` (or Intl-only if it suffices — Task 3 decides with evidence). No new services.

**Spec:** `docs/superpowers/specs/2026-08-05-pwa-rework-design.md` §2 (data model incl. report_utc), §4 (API)
**Design source:** approved hybrid-v2 mockup tokens — ground `#121418`, surface `#191d24`/`#1a2027`, border `#2b3442`, text `#dfe4ec`/bright `#f2f5fa`/muted `#8b93a3`, amber `#e2a63d`/numerals `#ffd57e` (time-critical only), ok/home `#8fd3b6`, away `#9db8e8`, violation `#e0655f` (legal breaches only), mono numerals via `font-variant-numeric: tabular-nums` + monospace time digits.
**UX rules (binding):** `.superpowers/research/crew-roster-ux-2026-08.md` — R1 one line per duty; R3 report time primary/departure secondary; R4 absolute+relative time pairing; R6 pairing = one visual unit; R9/R10 contrast (report-time numerals ≥7:1 on their surface).

## Global Constraints

- Branch: all work on `feat/plan3-trips`. Never commit to `main`.
- Full gate at every task's end: `pnpm typecheck && pnpm test` green all workspaces + `pnpm --filter @roaster/web build` green when web touched.
- All flight times stored as UTC ISO strings + IANA tz strings both ends (`dep_utc/arr_utc/report_utc`, `dep_tz/arr_tz`); render local; NEVER store local-only times.
- `report_utc` default = `dep_utc − 90 minutes`, always editable, nullable never (backfilled on create).
- API auth: every /api/trips route 401s without session (middleware already provides `c.var.user`); ownership: users only read/write their own rows — one helper, used everywhere.
- Validation: zod schemas in `shared/src` — single source for client + server.
- Amber reserved for time-critical numerals; red `#e0655f` only for legal violations (currently unused — do NOT use it for errors/delete buttons; UI errors use muted styling).
- Migrations via existing pipeline: schema.ts → `drizzle-kit generate` → `drizzle/` → `wrangler d1 migrations apply` (local + remote) — same dir feeds tests.
- Commit trailers as used on this branch (Co-Authored-By + Claude-Session).

### Task 4: Trips CRUD API

**Files:**
- Create: `worker/src/trips.ts` (Hono sub-router), `worker/test/trips.test.ts`; Modify: `worker/src/index.ts` (mount)

**Interfaces:**
- Consumes: session middleware (`c.var.user`), zod schemas from shared, tables from Task 2.
- Produces endpoints (all 401 unauthenticated; zod 400 on bad input):
```
GET    /api/trips?from&to     → { trips: (Trip & { flights: Flight[] })[] } (only mine; from/to filter on dep_utc, optional)
POST   /api/trips             body TripInput → 201 created trip+flights; report_utc backfilled via reportDefault() when absent; dep_tz/arr_tz resolved from airports table by IATA (400 if airport unknown)
PATCH  /api/flights/:id       partial LegInput → 200 updated (ownership enforced)
DELETE /api/trips/:id         → 204 (cascade deletes flights)
```
- Produces: `requireOwn(db, table, id, userId)` helper — 404 on missing OR not-owned (no existence leak).
